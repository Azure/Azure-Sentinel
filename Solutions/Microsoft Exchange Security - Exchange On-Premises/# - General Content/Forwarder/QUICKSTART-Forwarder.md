# Forwarder Pickup Processor quick start

The Forwarder Pickup Processor sends JSON files generated by `CollectExchSecIns.ps1` to Microsoft Sentinel. Use it when the collector writes data to a pickup folder instead of sending data directly.

For complete configuration and troubleshooting information, see [Forwarder Pickup Processor](./README-ForwarderPickup.md).

## 1. Prerequisites

Verify that:

- The `Forwarder` folder from the latest collector package is available on the forwarding server.
- Windows PowerShell 5.1 is available.
- `Az.Accounts` is installed.
- The Azure Monitor connector has already created the DCE and DCR.
- The forwarding identity has **Monitoring Metrics Publisher** on the DCR.
- Certificate authentication is configured for an unattended non-Azure server, or the server is an Azure VM with a system-assigned managed identity.

Run from an elevated Windows PowerShell session:

```powershell
Install-Module -Name Az.Accounts -Repository PSGallery -Scope AllUsers -Force
Get-Module -Name Az.Accounts -ListAvailable
```

## 2. Configure the collector pickup output

In `Config\CollectExchSecConfiguration.json`, enable the forwarder under `LogCollection`:

```json
{
  "LogCollection": {
    "ActivateLogUpdloadToSentinel": "true",
    "UseForwarder": "true",
    "ForwarderPickupPath": "C:\\ESI\\ForwarderPickup",
    "LogTypeName": "ESIExchangeConfig"
  }
}
```

The pickup path must match the `PickupFolder` value in `Forwarder\Config\ForwarderPickupConfig.json`.

## 3. Configure the Forwarder

Back up and edit:

```powershell
Copy-Item `
    ".\Forwarder\Config\ForwarderPickupConfig.json" `
    ".\Forwarder\Config\ForwarderPickupConfig.backup.json"

notepad ".\Forwarder\Config\ForwarderPickupConfig.json"
```

Example for certificate authentication:

```json
{
  "PickupFolder": "C:\\ESI\\ForwarderPickup",
  "ArchiveFolder": "C:\\ESI\\Archive",
  "ErrorFolder": "C:\\ESI\\Error",
  "LogFolder": "C:\\ESI\\Logs",
  "DeleteAfterProcessing": false,
  "MaxFilesPerRun": 100,
  "FilePattern": "*.json",
  "SentinelConnection": {
    "UseManagedIdentity": false,
    "UseLogIngestionAPI": true,
    "DataCollectionEndpointURI": "https://your-dce.ingest.monitor.azure.com",
    "DCRImmutableId": "dcr-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx",
    "TenantID": "your-tenant-id",
    "ApplicationId": "your-application-id",
    "CertificateThumbprint": "your-certificate-thumbprint",
    "DefaultLogType": "ESIExchangeConfig",
    "MaxSegmentSizeMb": 0.9
  },
  "Proxy": {
    "UseProxy": false,
    "ProxyUrl": ""
  }
}
```

For an Azure VM with a system-assigned managed identity, set `UseManagedIdentity` to `true` and run the scheduled task as `SYSTEM`.

## 4. Test manually

Run the collector once to create a JSON file in the pickup folder. Then run:

```powershell
.\Forwarder\ForwarderPickupProcessor.ps1 `
    -ConfigurationFile ".\Forwarder\Config\ForwarderPickupConfig.json" `
    -MaxFilesPerRun 1
```

Confirm that:

- The file moves from `PickupFolder` to `ArchiveFolder`.
- Failed files move to `ErrorFolder`.
- A `ForwarderProcessor_*.log` file appears in `LogFolder`.

## 5. Install the scheduled task

For a service account:

```powershell
.\Forwarder\Install-ForwarderScheduledTask.ps1 `
    -ServiceAccount "CONTOSO\svc-esi" `
    -IntervalMinutes 15
```

For an Azure VM managed identity:

```powershell
.\Forwarder\Install-ForwarderScheduledTask.ps1 `
    -UseSystemAccount `
    -IntervalMinutes 15
```

The installer requires administrator privileges and can start the task immediately for testing.

## 6. Validate ingestion

```kql
ESIAPIExchangeOnPremConfig_CL
| where TimeGenerated > ago(1h)
| summarize Records = count(), LastIngestion = max(TimeGenerated)
```

Check the task:

```powershell
Get-ScheduledTask -TaskName "ESI Forwarder Processor" |
    Get-ScheduledTaskInfo
```

If ingestion fails, review [Forwarder troubleshooting](./README-ForwarderPickup.md#troubleshooting).
