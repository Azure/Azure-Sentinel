| 3.2.0       | 14-09-2026                     | Replaced the **Check_Point_EM_Importer** playbook with a scheduled analytic rule, **Check Point Exposure Management - Argos alerts to incidents**, that reads `argsentdc_CL` directly. The playbook wrote alerts to the built-in `SecurityAlert` table through the Logs Ingestion API, which does not support that table, so its data collection rule was rejected at creation and the playbook could never complete its ingestion step. The analytic rule produces the incident, the attached alert and the `ref_id` Custom Detail natively, removing the data collection endpoint, data collection rule, managed identity role assignment and the fixed polling window. Added the **Check_Point_EM_AutomationRules** template to the package so the Exporter playbook is actually bound to incident updates; it shipped in the repository but was never referenced by the solution, leaving outbound status sync unwired. Fixed `ref_id` extraction in the **Check_Point_EM_Exporter** and **Check_Point_EM_ManualStatusUpdate** playbooks. Sentinel delivers `Custom Details` in the incident trigger payload as a JSON string whose values are arrays, so the previous expression failed at runtime with "Property selection is not supported on values of type 'String'". It now parses the string with `json()` and takes the first array element. |
| 3.1.4       | 08-09-2026                     | Fixed **Check_Point_EM_Importer** playbook creation failing with `InvalidTemplate: Unable to parse language expression '': expected token 'Identifier' and actual 'EndOfData'`. The empty `Entities` JSON array literal in the SecurityAlert ingestion body was interpreted by ARM as an empty template expression; it is now emitted via `string(createArray())` in both the solution package and the standalone playbook template. |
| 3.1.3       | 21-08-2026                     | Fixed ARM template expression escaping in nested content templates (stray `]` in dcrConfig and playbook expressions) that caused data connector **Connect** deployment to fail with a template language expression parse error.<br>Fixed alerts polling request body to send strict JSON (double-quoted): the Argos API now rejects single-quoted bodies with 422 Unprocessable Entity.<br>Fixed connection template parameter defaults: placeholder values (e.g. `"severity"`) leaked into the API request body when optional connector fields were left empty, failing the connectivity check with 422 (invalid severity enum). Optional filters now default to empty and are omitted from the request. |
