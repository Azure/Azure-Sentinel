| 3.2.0       | 21-09-2026                     | • **Argos → Microsoft Sentinel status sync.** Status changes made in Argos are now mirrored onto the matching incidents.<br>• **Microsoft Sentinel → Argos sync is not included in this version.** The Argos API accepts its token only as a cookie, and Azure Logic Apps removes the `Cookie` header from outgoing requests, so no playbook can authenticate to Argos. The **Check_Point_EM_Exporter**, **Check_Point_EM_ManualStatusUpdate** and **Check_Point_EM_AutomationRules** templates are therefore not shipped in 3.2.0. The same limit applies to the enrichment and response playbooks, whose Argos calls return HTTP 401. The data connector is unaffected: the Codeless Connector Platform sends the key itself.<br>• **Data connector** polls on `update_date` instead of `created_date`, so every change to an Argos alert adds a row to `argsentdc_CL`, and requests 100 alerts per page instead of the API default of 10, which had silently capped ingestion at 10 alerts per polling window.<br>• **New analytic rule, Check Point Exposure Management - Argos alerts to incidents**, replaces the **Check_Point_EM_Importer** playbook. The Importer wrote to the built-in `SecurityAlert` table through the Logs Ingestion API, which does not support that table, so it could never ingest. The rule creates one incident, with an attached alert and the `ref_id` Custom Detail, the first time an alert appears as `open` or `acknowledged`; later changes to the alert never create another incident.<br>• **New playbook, Check_Point_EM_InboundStatusSync**, applies Argos status changes to the matching incident every 5 minutes, mapping closure reasons to Microsoft Sentinel classifications. It uses its managed identity for the workspace query and the incident update, so it needs no Argos credentials.<br>• **`ref_id` extraction fixed** in the FetchAttachments and PhishingTakedown playbooks. Microsoft Sentinel delivers `Custom Details` as a JSON string of arrays, so the previous expression failed with "Property selection is not supported on values of type 'String'".<br>• **`API_Base_URL` takes the tenant URL** (for example `https://your_tenant.cyberint.io`), the same value as the data connector, in the FetchAttachments and PhishingTakedown playbooks. The service path is added automatically; values ending in `/alert` keep working. PhishingTakedown now submits to `/takedown/api/v1/submit`.<br>• **Workbook** summary tiles count each alert once by its latest status.<br>• **Upgrading from 3.1.x:** reconnect the data connector so it polls on `update_date`; create a rule from the Argos alerts to incidents template; create the InboundStatusSync playbook and grant it the **Microsoft Sentinel Responder** role; disable the automation rule that runs the Exporter, along with any existing **Check_Point_EM_Importer** Logic App, its API connections and its data collection endpoint. `argsentdc_CL` now holds one row per alert change, so custom queries should take the latest row per `ref_id`. |

Optional filters now default to empty and are omitted from the request. |
