| **Version** | **Date Modified (DD-MM-YYYY)** | **Change History** |

| 3.0.2 | 21-10-2026 | Fixed the high-confidence threat rule to compare the decimal confidence score (0 to 1) with `todouble(confidence) >= 0.8`; replaced the fixed 5,000-per-hour NRD burst threshold with a seven-day daily baseline comparison. The **Feeds to enable** selection on the connector page now controls which of the seven feed pollers are created; unselected feeds are not provisioned. Raised the retention of the two NRD tables from 4 to 30 days so the NRD analytic rules have their full 7-day and 8-day look-back windows; the threat table stays at 4 days because its rules read at most the last six hours. Fixed the feed fetch step sending a literal `{{apiKey}}` placeholder instead of the API key. The NRD-seen-in-threat-feed rule now matches threat rows from the last hour so it no longer re-alerts hourly for a day. Pollers skip the fetch when the status date is older than yesterday or not a date. Removed stray `workspaceResourceId` and `provisioningState` properties from the DCR. The parked-threat-domain rule now matches the feed's `t` flag value; it previously tested for `true` or `1` and never fired. The feed selection on the connector page no longer defaults to all feeds and requires at least one selection. The connector page's Data received chart now shows one line per feed so the enabled feeds are visible after a reload, and an info message explains that the selection is not read back from the workspace. Table definitions now set `totalRetentionInDays` alongside `retentionInDays` so retention changes on existing tables succeed. |
| 3.0.1 | 16-10-2026 | Deployment UI now filters workspaces by the exact resource group and lets the workspace region be reviewed before deployment. |
| 3.0.0 | 09-10-2026 | Initial publication with the CCF threat and NRD feeds and four analytic-rule templates. |
